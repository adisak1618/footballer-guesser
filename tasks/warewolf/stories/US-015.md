# US-015: `<ArchetypeChipStrip>` (multi-select)

**Lane:** E. Components
**Depends on:** US-003, US-009
**Priority:** 15

## Description
As a player, I need a multi-select filter strip above the setup list so I can narrow recommendations to one or more archetypes I'm in the mood for.

## Acceptance Criteria
- [ ] `apps/warewolf/components/ArchetypeChipStrip.tsx`.
- [ ] Props: `playerCount: number`, `activeFilters: Set<ArchetypeId>`, `onChange: (next: Set<ArchetypeId>) => void`.
- [ ] Renders one chip per archetype in `ARCHETYPES` whose `[minPlayers, maxPlayers]` includes `playerCount`. Hidden chips do NOT render.
- [ ] Each chip shows: archetype seal glyph + en/th display name (only the selected language renders, per reconciliation — handle in caller via next-intl).
- [ ] **Multi-select** — tapping a chip toggles it in `activeFilters`. Empty set = "show all". Visual styling distinguishes selected/unselected (selected = blood-red outline, parchment darker fill).
- [ ] Tap target ≥ 44px (per Pass 6); visual chip can be smaller with invisible padding.
- [ ] Keyboard: chips are buttons; Enter/Space toggle; arrow keys navigate within the strip per Pass 6.
- [ ] Focus ring 2px blood-red @ 2px offset per Pass 6.
- [ ] Tests written: `apps/warewolf/components/ArchetypeChipStrip.test.tsx`:
  - At playerCount=5, `wolf-chaos`+`social-bluff` chips render, `info-heavy`+`neutral-mayhem` are hidden.
  - At playerCount=14, `wolf-chaos`+`beginner`+`social-bluff`+`neutral-mayhem` hidden.
  - Tap fires `onChange` with toggled set.
- [ ] Typecheck passes: `cd apps/warewolf && bunx tsc --noEmit`.
- [ ] Lint passes: `bun run lint`.
- [ ] Verify in browser using dev-browser skill.

## Technical Notes
- Wired up by `useWarewolfStore` in US-018 and consumed by `/setup` page in US-020.
- "Empty filter = show all" is the documented default per design doc UI flow.
