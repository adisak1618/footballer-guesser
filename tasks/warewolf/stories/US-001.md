# US-001: Roles data — `packages/content/werewolf-roles.ts`

**Lane:** A. Data
**Depends on:** none
**Priority:** 1

## Description
As a developer, I need a typed, frozen role catalog so the solver, validator, UI, and card-art pipeline all read the same source of truth for the 22 V1 roles.

## Acceptance Criteria
- [ ] File created at `packages/content/werewolf-roles.ts` and exported from `packages/content/src/index.ts`.
- [ ] Exports `ROLES: Readonly<Record<RoleId, Role>>` as a frozen const.
- [ ] Includes all 22 V1 roles per design doc Premise #8 (line 286–293):
  - Wolf-team (5): werewolf, wolf-cub, alpha-wolf, minion, sorceress
  - Village info (4): seer, apprentice-seer, aura-seer, paranormal-investigator
  - Village power (8): witch, bodyguard, hunter, tough-guy, prince, priest, mayor, drunk
  - Village vanilla/social (4): villager, mason, spellcaster, old-hag
  - Neutral (4): tanner, lone-wolf, hoodlum, cult-leader
- [ ] **Excluded** (per Premise #8): cursed, doppelganger, cupid, diseased, ghost, lycan, lone-other.
- [ ] Each role has: `id`, `team` (`village` | `werewolf` | `neutral`), `category` (`info` | `protection` | `kill` | `vote` | `chaos` | `vanilla` | `neutral`), `balance` (signed int from `apps/warewolf/source/game-rule/role-balance.md`), `i18n: { en, th }` with `name`, `short`, `description`, and `cardArtPath` referencing `packages/content/card-art/<id>.webp` (file exists post-US-012).
- [ ] Type `RoleId` is a union of literal string IDs (used by solver, validator).
- [ ] Tests written: `packages/content/werewolf-roles.test.ts` asserting (a) exactly 22 roles, (b) every role has both en + th names, (c) `RoleId` union matches keys, (d) balance values are signed ints.
- [ ] Typecheck passes: `cd packages/content && bunx tsc --noEmit` (use workspace if `packages/content` has its own).
- [ ] Lint passes: `bun run lint`.
