# US-006: Validator — `apps/warewolf/lib/validator.ts`

**Lane:** A. Data
**Depends on:** US-001
**Priority:** 6

## Description
As a developer, I need a pure-function validator that determines whether a setup is Playable, returning blocker codes, balance, and team sums for the Playable banner and balance scale to render.

## Acceptance Criteria
- [ ] File created at `apps/warewolf/lib/validator.ts`.
- [ ] Exports `validate(setup: RoleId[], playerCount: number): { ok: boolean; blockers: BlockerCode[]; balance: number; wolfSum: number; villageSum: number; wolfCount: number; villageCount: number; neutralCount: number }`.
- [ ] Blocker codes (union of string literals):
  - `'no-wolves'` — fired when wolf count === 0.
  - `'wolves-gte-village'` — fired when wolf count ≥ village count (neutrals **excluded** from parity check, per design doc Premise #3).
  - `'role-count-mismatch'` — fired when `setup.length !== playerCount`.
  - `'unknown-role'` — fired when any `RoleId` in `setup` is not in `ROLES`. **Strict** per Eng Review decision #3.
- [ ] **Single-pass over `setup`** per Eng Review code-quality fix (replaces prototype's three loops at `finalized.html:792–818`).
- [ ] `ok` is `true` iff `blockers.length === 0`.
- [ ] `balance`, `wolfSum`, `villageSum` computed in the same single pass.
- [ ] Tests written: `apps/warewolf/lib/validator.test.ts`:
  - `no-wolves` blocker fires on all-village setup.
  - `wolves-gte-village` fires on wolves ≥ village (with neutrals excluded from parity).
  - `role-count-mismatch` fires when setup length ≠ playerCount.
  - `unknown-role` blocker fires when any id not in `ROLES`. Note: this path is normally unreachable in production because `decodeSetup` substitutes unknowns (US-007), but the validator must reject as a type-contract guarantee per Eng Review decision #3.
  - All-OK happy path returns `ok: true` and correct sums.
  - **fast-check property:** any randomly generated valid setup passes.
  - **fast-check property:** any randomly generated no-wolves setup returns `no-wolves` blocker.
- [ ] Typecheck passes: `cd apps/warewolf && bunx tsc --noEmit`.
- [ ] Lint passes: `bun run lint`.

## Technical Notes
- Per Eng Review decision #3: validator is **the strict line of defense**; the parser (US-007) is the only place that substitutes unknown ids. This split makes the validator's type contract enforceable.
- Single-pass refactor is non-negotiable (DRY preference; matches user's stated style).
- Hard-rule enforcement details in design doc lines 528–551.
- Add `fast-check` to apps/warewolf devDependencies in US-009 if not yet present.
