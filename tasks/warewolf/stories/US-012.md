# US-012: Card art pipeline — Sharp WebP conversion

**Lane:** D. Card art
**Depends on:** US-001
**Priority:** 12

## Description
As a developer, I need a one-shot build script that converts the existing source JPGs into optimized WebP files in `packages/content/card-art/`, so the app loads compact card art via `next/image` and the source JPG tree stays out of the deployed bundle.

## Acceptance Criteria
- [ ] `apps/warewolf/scripts/build-cards.ts` exists, using Sharp.
- [ ] Reads from `apps/warewolf/source/processed/warewolf-card-cropped/*.jpg`.
- [ ] Writes to `packages/content/card-art/<roleId>.webp` at **512×768@85** quality.
- [ ] Wired as `bun run build:cards` script in `apps/warewolf/package.json`.
- [ ] `packages/content/src/index.ts` exports a `cardArtPath(roleId: RoleId): string` helper resolving to the public path consumable by `next/image`.
- [ ] Script is idempotent — re-running skips up-to-date outputs (compare mtime or hash).
- [ ] Documents path resolution: how `next/image` finds these. Either (a) bundle as imports via Next.js' `@/` resolver into `apps/warewolf/public/cards/` symlink, or (b) static URL strategy. Pick one, document the choice in a top-of-file comment.
- [ ] **Card art remains the existing photos of Bezier Games Ultimate Werewolf cards** per Eng Review decision #1 (user accepted IP risk). No watermarking, no attribution overlay.
- [ ] Tests written: `apps/warewolf/scripts/build-cards.test.ts`:
  - Running the script on a temp dir produces correctly-sized WebP files.
  - Idempotency: running twice doesn't reprocess unchanged sources.
- [ ] `bun run build:cards` produces 22 WebP files (one per V1 role).
- [ ] Typecheck passes: `cd apps/warewolf && bunx tsc --noEmit`.
- [ ] Lint passes: `bun run lint`.

## Technical Notes
- Per Eng Review decision #1: ship existing JPG photos as WebP; user accepted IP risk.
- Total bundle estimate: 22 cards × ~30KB WebP ≈ 660KB. Acceptable.
- Use Sharp directly — no Next.js image optimizer for this (Sharp is faster + deterministic).
- Source JPGs are full-bleed, varied sizes; resize-to-fit 512×768 with letterboxing/cropping as needed.
