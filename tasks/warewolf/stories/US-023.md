# US-023: Balance audit property test (384 cells)

**Lane:** G. Tests + perf
**Depends on:** US-005
**Priority:** 23

## Description
As a maintainer, I need a property-style test that exercises every `(archetype × playerCount × variationIdx)` cell to guarantee the solver doesn't silently regress into unplayable rooms — the single most important regression net for V1.

## Acceptance Criteria
- [ ] Test added to `apps/warewolf/lib/solver.test.ts` (or new file `apps/warewolf/lib/solver-audit.test.ts`).
- [ ] Property test using `fast-check` or a manual cartesian-product loop:
  ```
  for each archetypeId in ARCHETYPES:
    for each playerCount in [minPlayers..maxPlayers]:
      for each variationIdx in [0, 1, 2]:
        assert |generateVariations(archetypeId, playerCount)[variationIdx].balance| ≤ 5
        OR the cell is hidden by minPlayers/maxPlayers gating
  ```
- [ ] Cell count: 8 archetypes × (avg 13 player counts) × 3 variations = ~312 cells. (Spec doc cited up to 384 max — that's the upper bound across all archetypes.)
- [ ] Test fails loudly when any cell exceeds `|balance| > 5`, naming the offending `(archetype, playerCount, variationIdx)` tuple.
- [ ] Test runs in < 5 seconds (acceptable for a CI gate).
- [ ] **Solver perf assertion** (separate test in same file): `computeSetupList(20)` completes in < 50ms (per Eng Review perf gate).
- [ ] Test runs on every PR via `bun run test`.
- [ ] Typecheck passes: `cd apps/warewolf && bunx tsc --noEmit`.
- [ ] Lint passes: `bun run lint`.

## Technical Notes
- This is the **regression net** for the solver — the most valuable test in the V1 suite.
- If a cell fails the audit, fix the seed (US-004) or the wolf pool (US-002), not the test threshold.
- 384 was the upper bound when balance audit was first run; the actual count depends on each archetype's `[min,max]Players` span.
