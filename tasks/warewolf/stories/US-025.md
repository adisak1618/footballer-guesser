# US-025: CI perf gates — bundle budget + Lighthouse CI

**Lane:** G. Tests + perf
**Depends on:** US-021
**Priority:** 25

## Description
As a maintainer, I need CI to fail when the customize page exceeds the bundle budget or when Lighthouse mobile LCP regresses past 2.5s, so perf doesn't silently drift between releases.

## Acceptance Criteria
- [ ] `@next/bundle-analyzer` added to `apps/warewolf/devDependencies` and wired in `next.config.ts`.
- [ ] CI script (e.g. `apps/warewolf/scripts/check-bundle-budget.ts`) reads `.next/build/...` output and asserts `/setup/customize` gzipped JS ≤ **96KB** (80KB target + 20% margin per Eng Review perf gate).
- [ ] Script exits 1 on regression, with a clear message naming the route + actual size + budget.
- [ ] Script wired as `bun run check:bundle` and called from a GitHub Action on every PR.
- [ ] **Lighthouse CI Action** wired in `.github/workflows/` (new or extend existing):
  - Runs against a Vercel preview deploy.
  - Asserts mobile LCP < **2.5s on simulated 3G**.
  - Fails the workflow on regression.
- [ ] Both gates are configured to ERROR (not warn). Per Eng Review perf decision.
- [ ] Initial baseline run captured and documented in a `apps/warewolf/PERF.md` note.
- [ ] Typecheck passes: `cd apps/warewolf && bunx tsc --noEmit`.
- [ ] Lint passes: `bun run lint`.

## Technical Notes
- Per Eng Review locked decision: bundle 80KB ±20% + Lighthouse mobile LCP < 2.5s.
- Lighthouse CI Action: https://github.com/treosh/lighthouse-ci-action — point at the Vercel preview URL surfaced by the `vercel-action` step.
- If `/setup/customize` is over budget on first run, this is a green field — fix at the source (split components, lazy-load, etc.) rather than raise the budget.
