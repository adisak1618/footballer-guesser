## Codebase Patterns

- Root `package.json` uses Bun workspaces (`apps/*`, `packages/*`). `apps/` and `packages/` dirs do not need to exist for `bun install` to succeed — empty globs are tolerated.
- Existing Headball app code lives at repo root through Phase 0; Phase 1 relocates it to `apps/headball/`.
- Turborepo v2 requires `packageManager` field in root `package.json` to resolve workspaces (currently `bun@1.1.29`).
- Turbo v2 schema uses `tasks` (not `pipeline`) — see `turbo.json`. Build outputs include `.next/**` (excluding cache) and `dist/**` for libraries.
- Bun 1.1.29 generates `bun.lockb` (binary), not `bun.lock` — turbo emits a harmless WARNING about parsing the lockfile but still functions; upgrading to Bun ≥1.1.42 (text lockfile) would silence it.
- Pre-existing tech debt: root `bun run lint` reports thousands of errors (eslint scope issue / type-aware rules in deps) — predates Phase 0 work, not a regression. Phase 1 relocation will likely scope eslint to `apps/headball/` and reduce the surface.
- Workspace packages under `packages/*` declare `"main": "./src/index.ts"`, `"types": "./src/index.ts"`, and `"exports": { ".": "./src/index.ts" }` so consumers import TS source directly (no build step) — matches D3 in the design doc.
- `next lint` is removed in Next 16 — do NOT add `"lint": "next lint"` to per-app `package.json`. Use `eslint` directly when wiring per-app lint (Phase 0.4/0.7).
- `.turbo/` (per-package turbo cache + logs) is gitignored at the repo root — covers every workspace package without repeating in each.
