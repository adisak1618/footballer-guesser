## Codebase Patterns

- Grimoire design tokens live in `docs/DESIGN-warewolf.md` (canonical) and are
  mirrored into `apps/warewolf/app/globals.css` (Tailwind v4 `@theme inline`).
  Token names match 1:1 between the two — when changing one, change the other
  in lockstep. Headball's Stadium Energy in `docs/DESIGN.md` is a SEPARATE
  system; do NOT cross-pollinate. Prototype `finalized.html:17-34` is the
  visual ground truth for hex values (the earlier design-doc text's
  `#f6ebd0` off-cream is superseded by the prototype's `--cream: #fbf4e0`).
- `@social-hub/content` is the cross-app source of truth for static role/content data.
  Place new role-data modules under `packages/content/src/` (NOT the package root) so
  the existing `tsconfig.json` (`include: ["src/**/*.ts"]`) and `vitest.config.ts`
  (`include: ["src/**/*.test.ts"]`) pick them up. Re-export from `src/index.ts`.
- Tests live next to the source as `src/<name>.test.ts` (vitest picks them up via
  the workspace-root vitest projects pointer plus the package-local config).
- Spec/typo note for V1 warewolf roles: design doc + story US-001 both say
  "22 V1 roles" but enumerate 25 named role IDs (5 wolf + 4 info + 8 power +
  4 vanilla + 4 neutral). The prototype `finalized.html` also has 25. Treat the
  enumerated list as the substantive contract; "22" is an upstream typo.
- Role.category enum is fine-grained (info/protection/kill/vote/chaos/vanilla/neutral);
  the customize-page 6-tab mapping in `lib/category-tabs.ts` (Eng Review decision #6)
  derives display tabs from team + category. Do not collapse the enum to match the
  prototype's coarse wolf/info/power/social/neutral.
- Lane A (US-002..US-008) files live under `apps/warewolf/lib/` but US-009
  (full Next.js scaffold) is later in build order. To make Lane A's per-package
  typecheck + tests work, US-002 added minimal `apps/warewolf/{package.json,
  tsconfig.json,vitest.config.ts}`. US-009 will replace/extend these with the
  full Next.js + Tailwind + Playwright scaffolding; do NOT remove the minimal
  files during US-009, only augment them.
- `ArchetypeId` literal-union is defined locally in `apps/warewolf/lib/wolf-pools.ts`
  for self-contained Lane A. US-003 (`lib/archetypes.ts`) is the canonical owner
  per the story spec; when implementing US-003, either re-export ArchetypeId from
  archetypes.ts and have wolf-pools.ts import it, or keep the single declaration
  here and have archetypes.ts import — pick whichever produces less churn.
- Solver SetupListItem is a discriminated union: Setup | SolverError (kind:
  'solver-error'). `isSolverError(item)` type-guards in consumers. Non-error
  rows sort by |balance| ASC; errors append at the end in archetype-declaration
  order. UI (US-014) consumes this list and renders <SolverErrorRow> on the
  marker.
- Bogus archetype ids passed to pickWolvesForBalance hit the empty-pool throw
  cleanly (WOLF_POOLS[badId] ?? [] -> throws). Use this in tests instead of
  trying to construct a singleton-only pool.
- `fast-check` is available in `apps/warewolf` devDependencies (added in US-006).
  Use `import fc from "fast-check"` for property tests; `fc.constantFrom(...ids)`
  + `fc.array` compose nicely with ROLE_IDS filters by team.
- Validator (`lib/validator.ts`) is single-pass and strict: unknown role ids are
  blockers (`'unknown-role'`). The parser (`lib/share-url.ts`, US-007) is the
  sole place that silently substitutes unknowns to `villager` — keep that
  single source-of-truth split per Eng Review decision #3.
- `zod` 4.3.6 is hoisted at the workspace root via Headball; warewolf declares
  `"zod": "^4.3.6"` in `apps/warewolf/package.json` to make the dependency
  explicit. Schemas with `.catch(fallback)` swallow validation errors and
  return the fallback — useful for graceful URL parsing where the URL is
  user-modifiable.
- decodeSetup pre-filters `lang` to `'en' | 'th' | undefined` BEFORE handing to
  Zod, so invalid values (e.g. `?lang=fr`) trigger `.default('en')` instead of
  the enum throwing. Same pattern works for any z.enum field reachable from
  user input.
