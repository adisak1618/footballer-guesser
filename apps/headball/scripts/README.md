# Seed pipeline

Three-step pipeline that builds the football player roster from Wikidata.

```
data/raw/{league}/{club}.json    ←  bun run seed:fetch    (Wikidata SPARQL → JSON, ~3 min, free)
data/seed/players.json           ←  bun run seed:build    (filter + dedup + tier)
data/seed/categories.json        ←  hand-edited (or kept on first build)
supabase/migrations/0010_*.sql   ←  bun run seed:sql      (resolves DSL → SQL)
data/premier-league.ts           ←  regenerated by seed:build (client-side autocomplete)
```

Raw fetches are grouped by league for navigability:

```
data/raw/
├── premier-league/      liverpool, man-united, arsenal, chelsea, man-city, tottenham
├── la-liga/             real-madrid, barcelona, atletico
├── serie-a/             ac-milan, inter, juventus
├── bundesliga/          bayern, dortmund
└── ligue-1/             psg
```

## One-shot refresh

```bash
bun run seed:all                 # fetch (skips cached) + build + sql
bunx supabase db reset           # apply the new migration locally
```

`seed:fetch` skips clubs whose JSON file already exists in `data/raw/`, so adding
one new club only fetches that one (~5 seconds instead of ~6 minutes). To force a
full refresh — e.g., after a transfer window when Wikidata has new player rows:

```bash
bun run scripts/fetch-wikidata.ts --force   # re-fetch every club
```

## Adding a new category

Edit `data/seed/categories.json`:

```json
{
  "slug": "dutch-strikers",
  "label_en": "Dutch nationality + Forward",
  "label_th": "นักเตะกองหน้าชาวดัตช์",
  "query": {
    "all": [
      { "field": "nationalities", "op": "contains", "value": "Kingdom of the Netherlands" },
      { "field": "position",      "op": "eq",       "value": "FWD" }
    ]
  }
}
```

Then `bun run seed:sql && bunx supabase db reset`. The DSL resolves the player set
at SQL-generation time and writes one row per match into `category_players`.

## Query DSL operators

| Op         | Field type    | Meaning                                    |
|------------|---------------|--------------------------------------------|
| `eq`/`neq` | scalar        | exact match / not match                    |
| `gt`/`gte` | number        | greater than / greater-or-equal            |
| `lt`/`lte` | number        | less than / less-or-equal                  |
| `contains` | array         | array contains the value                   |
| `in`       | scalar in arr | scalar is one of the supplied values       |
| `all`      | array of subs | every sub-query matches (AND)              |
| `any`      | array of subs | at least one sub-query matches (OR)        |
| `not`      | sub-query     | sub-query does NOT match                   |

Player fields available to the DSL: `id`, `name`, `name_th`, `nationalities`,
`birth_date`, `position`, `clubs_named`, `career_goals`, `sitelinks`,
`difficulty_tier`.

## Data sources

- **Wikidata SPARQL** for player profiles, names (en + th), nationality, DOB,
  career clubs, position, sitelinks (fame proxy). Free, unlimited.
- API-Football was evaluated and dropped — historical squad data only goes back
  to ~2018, and the per-player call cost was prohibitive for the use case.
- Trophies (UCL/PL titles/etc.) are deferred. When needed, hand-curate
  `data/seed/historical-trophies.json` keyed by Wikidata QID.

## What gets dropped during seed:build

The fame filter keeps a player if **either** condition holds:
- Has a Thai Wikipedia label (Thai audience signal), OR
- Has ≥30 sitelinks (Wikipedia article in 30+ languages, global signal)

A second football-credibility gate then drops anyone with no recorded position
AND fewer than 2 career clubs — this catches celebrities (actors, politicians)
who briefly appeared on a youth roster.

Result on current data: 14,959 raw rows → 2,138 unique players.
