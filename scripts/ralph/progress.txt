## Codebase Patterns
- Migrations live in `supabase/migrations/NNNN_*.sql`. Apply locally with `bunx supabase db reset` (re-runs every migration from scratch — keep them idempotent or order-correct).
- All client writes go through Postgres SECURITY DEFINER functions. RLS only grants SELECT to `anon`; never add INSERT/UPDATE/DELETE policies for `anon`.
- Realtime: any new table the client subscribes to must be added to `supabase_realtime` publication via `alter publication supabase_realtime add table <name>;` inside the migration that creates it.
- Use `bun` / `bunx` (not npm). `bunx tsc --noEmit` for typecheck, `bun run lint` for lint.
- Local Postgres: `PGPASSWORD=postgres psql -h 127.0.0.1 -p 54322 -U postgres -d postgres` for ad-hoc verification queries.
- The schema in `docs/PLAN.md` line 105 has `index(category)` inside the table body — that is pseudocode, not valid PG. Use a separate `create index ... on football_players(category);` statement.
- Postgres functions that `returns table (room_id uuid, player_id uuid, ...)` create implicit OUT params that shadow table columns of the same name. Add `#variable_conflict use_column` after `as $$` so identifiers in the body resolve to columns.
- `position` is a reserved word in `returns table (...)`. Quote it: `returns table (..., "position" int, ...)`.
- `0002_*.sql` is now `0002_functions.sql` (atomic write fns). The seed migration referenced as `0002_seed_players.sql` in PLAN.md / US-003 must instead be authored as `0003_seed_players.sql`.
- Function security pattern: `security definer` + `set search_path = public`, then at the bottom `revoke execute ... from public; grant execute ... to anon;`. Anon never gets direct INSERT/UPDATE.
- SQL string literals: escape apostrophes by doubling them (`'N''Golo Kante'`). Backslash escapes do NOT work in PG standard strings.
- Seed migrations: rely on table unique constraints + `on conflict (...) do nothing` for idempotency. `bunx supabase db reset` runs migrations in numeric order; the legacy `supabase/seed.sql` is unused (benign warning).
- Validate `scripts/ralph/prd.json` with `bunx node -e "JSON.parse(require('fs').readFileSync('scripts/ralph/prd.json','utf8'))"` at the start of every iteration — past iterations have left it malformed.
- PG → Thai error mapping for `join_room`: P0002 → 'ห้องไม่พบ', P0003 → 'เกมเริ่มแล้ว', P0004 → 'ห้องเต็ม', P0001 → 'ชื่อไม่ถูกต้อง'. Always switch on `error.code` (not message). Verify codes via `do $$ ... exception when others then raise notice 'code=%, msg=%', SQLSTATE, SQLERRM; $$;` in psql.
- Server actions that wrap a single RPC don't need the `lib/room-code.ts`-style helper — call `supabase.rpc('<fn>', { ... })` directly, then dispatch a custom error mapper. Reserve helper modules for retry-loops or multi-statement orchestration.
- Sanitize the room-code input on every keystroke: `value.toUpperCase().replace(/[^A-Z0-9]/g, '').slice(0, 6)`. The displayed value mirrors what Zod accepts so users never see "valid-but-rejected" states.
- Form fields with two errors should split the state shape: `{ code?, name?, form? }` with `form` reserved for server-returned messages, and `code` / `name` for client-side Zod failures. Render each in its own slot — never merge into a single string or you lose `aria-describedby` precision.

Use `bunx supabase gen types typescript --local 2>/dev/null > lib/database.types.ts` or just plain `>` redirect.

- Zod v4 `z.uuid()` validates RFC 4122 strictly: requires the version nibble (1/2/3/4/5/7/8) at char 14 AND the variant nibble (8/9/a/b) at char 19. PG's `uuid` type accepts any 32-hex-char shape, so a "looks-like-a-UUID" string can pass PG and fail Zod. Always generate test UUIDs via `crypto.randomUUID()`, not by typing `33333333-4444-5555-6666-777777777777` (variant nibble is `6` → fails).
- `rooms.host_player_id` and `players.player_id` both store the localStorage UUID (the same value the client passes to `create_room` / `join_room` / `start_round`). NOT `players.id` (the row PK). PRD/PLAN sometimes calls slot 8 "teal" but the design token is `tag-cyan` — use the existing token. Static maps are required because Tailwind v4 cannot resolve dynamic class names like `bg-tag-${color}`.
- Realtime pattern for a room view: `supabase.channel('room:${roomId}').on('postgres_changes', { event:'*', schema:'public', table:'rooms', filter: 'id=eq.${roomId}' }, ...).on(... table:'players', filter: 'room_id=eq.${roomId}' }, ...).subscribe(status => ...)`. On any players-table change, REFETCH the full ordered list (`select * from players where room_id=... order by join_order`) instead of diffing payloads — it's simpler, atomic, and stays correct on inserts/deletes/idempotent rejoin updates. Channel cleanup goes through `supabase.removeChannel(channel)` in the effect's return.
- `subscribe(status)` callback receives `'SUBSCRIBED' | 'CHANNEL_ERROR' | 'TIMED_OUT' | 'CLOSED'`. Map these to the store's `connectionStatus`: SUBSCRIBED → SUBSCRIBED, others → DISCONNECTED. Pre-subscribe state is CONNECTING.

- Page-level data lifecycle: do `setRoom/setPlayers/setMe` from a single `useEffect` keyed on the route param. Capture an `active` flag for cleanup so that an unmount mid-fetch doesn't write stale state. Call `reset()` from the store on unmount so navigating away clears stale room/players for the next visit.
- Lobby UX details: room code input/display always uses `font-hero` (Bebas) `text-[48px] tracking-[8px]` (matches DESIGN.md `room-code` token; the existing `tracking-[8px]` arbitrary-value pattern is established by US-009's join input). - All non-trivial state mutations on `rooms` (status changes, round increment) MUST go through a SECURITY DEFINER PG function — anon has only SELECT via RLS, no UPDATE policy. Bundle the host check + multi-table writes into one fn so anon can't get the room into a partial state on a half-failed write.

- **Learnings for future iterations:**
  - `me.player_id` (NOT `me.id`) is the correct join key into `round_state` rows — `round_state.player_id` references the localStorage UUID (the `rooms.host_player_id` / `players.player_id` column), same convention as the existing host-detection pattern. `players.id` is reserved for React keys only.
  - Tailwind v4 arbitrary breakpoint variants like `min-[375px]:` are the right tool for DESIGN.md responsive rules that don't fit the default `sm/md/lg` scale. The PRD's <375px guard maps to `text-[96px] min-[375px]:text-[144px]` directly — no `@theme` extension needed.
  - `room.current_round` is `number | null` in the generated types because of the server-side `default 0`. Coalesce with `?? 0` before passing into a child typed as `number`. Same pattern as `total_score ?? 0` from US-006. Generated nullable types are infectious — apply the coalesce at the call boundary, not deep in the component tree.
  - Per-status realtime subscriptions go in per-status containers (`lobby.tsx`, `playing.tsx`, future `results.tsx`), NOT in `page.tsx`. The page-level component owns rooms+players (room-wide). This way round_state's channel mounts only during PLAYING and unmounts cleanly on round-end / leave-room — no useEffect guards on `room.status` to short-circuit.
  - Channel name format: `room:${roomId}:<table>` to keep separate from the page-level `room:${roomId}` channel. Supabase realtime allows multiple channels per client but they must have distinct names.
  - Static class-name maps must duplicate per file because Tailwind v4 tree-shakes literal class strings. `name-card.tsx` and `lobby.tsx` both define their own TAG_BG/TAG_TEXT. If a 3rd consumer arrives, lift the literals into `lib/tag-colors.ts` (exporting the `Record<number, string>` directly so Tailwind still sees the strings at build time).
  - Wake Lock notes: lib.dom.d.ts already types `Navigator.wakeLock` and `WakeLockSentinel` (TS lib >= 5.0). Don't add `// @ts-expect-error`. Always feature-detect via `'wakeLock' in navigator` because Firefox Android and some webviews don't ship it. Always swallow errors — the API rejects on hidden tabs / battery saver / permission denied, and there's no user-actionable recovery; logging would just spam the console on every tab switch.
  - The PRD says caption is "tap to act" (Latin caption per DESIGN.md). Don't translate to Thai — the existing pattern uses Latin all-caps for `Round X/Y`, scoreboard, room code. Thai copy is reserved for action/body text. Apply the same rule to the OUT badge ('OUT' stays Latin all-caps in `font-display`).
  - The NameCard's onClick handler is deliberately NOT wired in US-012 — tap-to-cover is US-013's scope. Render the card as a `<main>` (semantic landmark) with no interactive role; US-013 will add the overlay sibling and route taps to it.
