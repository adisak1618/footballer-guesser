## Codebase Patterns
- Migrations live in `supabase/migrations/NNNN_*.sql`. Apply locally with `bunx supabase db reset` (re-runs every migration from scratch — keep them idempotent or order-correct).
- All client writes go through Postgres SECURITY DEFINER functions. RLS only grants SELECT to `anon`; never add INSERT/UPDATE/DELETE policies for `anon`.
- Realtime: any new table the client subscribes to must be added to `supabase_realtime` publication via `alter publication supabase_realtime add table <name>;` inside the migration that creates it.
- Use `bun` / `bunx` (not npm). `bunx tsc --noEmit` for typecheck, `bun run lint` for lint.
- Local Postgres: `PGPASSWORD=postgres psql -h 127.0.0.1 -p 54322 -U postgres -d postgres` for ad-hoc verification queries.
- The schema in `docs/PLAN.md` line 105 has `index(category)` inside the table body — that is pseudocode, not valid PG. Use a separate `create index ... on football_players(category);` statement.
- Postgres functions that `returns table (room_id uuid, player_id uuid, ...)` create implicit OUT params that shadow table columns of the same name. Add `#variable_conflict use_column` after `as $$` so identifiers in the body resolve to columns.
- `position` is a reserved word in `returns table (...)`. Quote it: `returns table (..., "position" int, ...)`.
- `0002_*.sql` is now `0002_functions.sql` (atomic write fns). The seed migration referenced as `0002_seed_players.sql` in PLAN.md / US-003 must instead be authored as `0003_seed_players.sql`.
- Function security pattern: `security definer` + `set search_path = public`, then at the bottom `revoke execute ... from public; grant execute ... to anon;`. Anon never gets direct INSERT/UPDATE.
